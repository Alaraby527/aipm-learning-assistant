## 业务背景

AI 产品经理是 2025-2026 校招最热门的方向之一，但求职者面临三个问题：

1. **知识零散**：网上关于 AI PM 的文章、视频、帖子很多，但没有系统化的学习路径，求职者不知道"学到什么程度才算够"
2. **缺少练习**：看了很多文章，但真要回答"怎么评测一个 Agent"这类问题时就答不上来——缺少结构化的刷题和自测
3. **进度不可见**：学了什么、学了多少、哪里薄弱，全凭感觉，没有反馈闭环

本项目验证的核心问题：**能否把零散的 AI PM 知识组织成有路径、有练习、有自测的系统化学习体验，同时保持零后端成本的纯前端架构？**

## 问题来源与用户调研

这个选题来自我自己和身边同学准备 AI PM 秋招的真实经历：

### 观察到的现象

1. **收藏即学会的错觉**：我在飞书文档里收藏了 200+ 篇 AI PM 相关文章，但面试前发现大部分没看过，看过的也记不住。问题不是没有资料，而是没有学习路径和反馈机制
2. **刷题无门**：LeetCode 有明确的题库和判题标准，但 AI PM 面试题没有——"怎么设计一个 RAG 系统""Agent 幻觉怎么处理"，这些题不知道标准答案是什么，也不知道自己答得好不好
3. **自测无标准**：不知道自己的水平在什么位置，哪些能力强、哪些弱，只能海投然后等面试结果反馈，周期太长
4. **知识地图缺失**：AIPM-Wiki 有 197 篇高质量文档，但直接扔给求职者会"信息过载"——需要按知识板块组织，让人知道从哪开始、按什么顺序学

### 用户访谈

访谈了 4 位同样在准备 AI PM 秋招的同学：

| 访谈发现 | 具体反馈 |
|----------|----------|
| 学习计划执行不下去 | "网上找了个 30 天计划，执行了 3 天就断了，没有打卡和追踪" |
| 面试题答案质量参差 | "牛客上的面经答案有的很浅，不知道什么是好的回答" |
| 不知道自己准备得怎么样 | "投了 20 家才知道自己项目经历这块弱，应该早点自测" |
| 资料太多反而焦虑 | "收藏了几百篇文章，越收藏越焦虑，根本看不完" |

### 为什么不用现成方案

| 方案 | 为什么不够 |
|------|-----------|
| 牛客/脉脉面经 | 答案质量参差，没有评分标准，无法系统练习 |
| Notion/飞书文档学习计划 | 没有打卡追踪、没有自测、没有互动，纯靠自律 |
| 在线课程（如三节课） | 收费高、内容更新慢、不针对 AI PM 方向 |
| 直接读 AIPM-Wiki | 197 篇文档没有学习路径，信息过载，不知道从哪开始 |

**结论**：需要的不是更多资料，而是一个**有路径、有练习、有自测、有进度追踪**的学习工具。

## 用户场景

- **目标用户**：准备 AI 产品经理校招/社招的求职者
- **核心场景**：
  1. 按 12 周学习计划系统学习，每天打卡追踪进度
  2. 刷面试题库，对照评分要点检查回答质量
  3. 完成 15 题五维能力自测，获取个性化评估和薄弱点
  4. 按知识地图浏览 197 篇文档，查漏补缺
- **边界**：不做社区/社交（避免分心）、不做 AI 答疑（纯前端无后端）、不做岗位推荐（聚焦学习本身）

## 产品决策

不是选"最先进的技术"，而是选"最适合这个场景的方案"：

| 决策点 | 选择 | 为什么不选另一个 |
|--------|------|------------------|
| 架构 | 纯前端 React 应用 | 学习数据是个人隐私，不需要后端；纯前端零运维成本，可部署到任意静态托管 |
| 数据存储 | localStorage | 学习进度、自测答案是个人数据，不上传服务器更安全；支持导出 JSON 备份 |
| 知识来源 | 内置 AIPM-Wiki 197 篇文档 | 自己写内容质量不可控、更新慢；AIPM-Wiki 是开源高质量知识库，CC BY-NC-SA 协议可使用 |
| 学习周期 | 12 周（8 周学习+4 周冲刺） | 30 天太短学不完，6 个月太长坚持不下来；12 周匹配秋招准备周期 |
| 自测题量 | 15 题选择题 | 不是题越多越好；15 题覆盖五维能力，10 分钟可完成，降低自测门槛 |
| 面试题库 | 20 题高频题 | 精选高频题，每题含评分要点和追问延伸；质量优先于数量 |
| 多档案支持 | 支持创建多个学习档案 | 一个人可能同时准备多个方向（AI PM / 产品运营），需要分开追踪进度 |

### 不做什么（MVP 边界）

- **不做 AI 答疑**：纯前端无后端，且 AI 答疑容易让学习者产生依赖，不如自己思考后对照评分要点
- **不做社区/社交**：学习是个人行为，社交功能会增加复杂度且分散注意力
- **不做岗位推荐/投递管理**：那是求职工作台的范畴（见 [qiuzhao-workbench](https://github.com/Alaraby527/qiuzhao-workbench)），本工具聚焦学习
- **不做后端同步**：学习数据存在本地，隐私安全；需要跨设备同步时用 JSON 导出/导入

## 功能特性

- **12 周学习计划**：8 周系统学习 + 4 周面试冲刺，共 84 天任务，支持打卡追踪
- **面试题库**：20 道高频面试题，每题含参考答案、评分要点、追问延伸和延伸阅读
- **能力自测**：15 道选择题覆盖五维能力（技术认知、产品基本功、数据与评估、商业判断、伦理与合规），完成后获取个性化评估
- **知识地图**：197 篇 AIPM-Wiki 文档全文内置，按知识板块分类浏览，支持文档内阅读
- **面经分享**：真实面试经验参考
- **学习原则**：七条核心学习原则和持续学习资源
- **多档案支持**：支持创建多个学习档案，数据本地存储，隐私安全

## 人机方案

| 环节 | 系统负责 | 人负责 |
|------|----------|--------|
| 学习路径 | 12 周计划自动排期，每日任务推荐 | 根据自身情况调整节奏 |
| 知识获取 | 197 篇文档分类浏览，知识地图导航 | 主动阅读和思考 |
| 练习反馈 | 面试题提供评分要点，自测提供五维评估 | 自己作答后对照检查 |
| 进度追踪 | 打卡记录、完成率统计、薄弱点识别 | 坚持执行，根据反馈调整 |

关键设计：本项目**不使用 AI 生成答案**——面试题的参考答案和评分要点是人工整理的，因为 AI 生成的答案可能不够准确或过于模板化，求职者需要看到高质量的参考答案来建立自己的判断标准。

## 使用流程

```
选择/创建学习档案
    ↓
查看仪表盘（学习进度、自测结果、薄弱点）
    ↓
按 12 周计划每日学习打卡
    ↓
刷面试题库（自己作答 → 对照评分要点 → 查看追问延伸）
    ↓
完成五维能力自测（15 题，10 分钟）→ 获取个性化评估
    ↓
按知识地图浏览 197 篇文档，查漏补缺
    ↓
数据本地存储，支持 JSON 导出备份
```

### 异常兜底

| 异常场景 | 处理方式 |
|----------|----------|
| localStorage 被清空 | 支持导入 JSON 备份恢复 |
| 文档内容加载失败 | 显示错误提示，不影响其他功能 |
| 自测未完成就退出 | 答案自动暂存，下次继续 |

## 技术栈

- **框架**：React 18 + TypeScript + Vite
- **路由**：React Router v7
- **样式**：Tailwind CSS + shadcn/ui
- **图标**：Lucide React
- **状态管理**：React Context + localStorage
- **UI 组件**：Radix UI primitives

## 数据隐私

所有学习数据（打卡记录、自测答案、档案信息）均保存在浏览器 localStorage 中，不会上传到任何服务器。支持导出 JSON 备份。

这是一个刻意的产品决策：学习数据是个人隐私，纯前端存储比后端数据库更安全；同时零后端成本意味着这个工具可以免费、长期运行。
